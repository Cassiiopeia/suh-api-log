# suh-api-log 3.0.0 설계

- 작성일: 2026-07-27
- 대상 버전: 2.0.3 → 3.0.0 (major, breaking)
- 한 줄 요약: 라이브러리가 자체 로깅을 고집하던 구조를 걷어내고 상위 프로젝트 로깅 설정에
  완전 위임하며, 레거시 데드코드를 제거하고 주요 동작을 전부 옵션·확장점으로 연다.

---

## 1. 배경 — 현재 코드의 문제

### 1.1 상위 프로젝트의 로깅 설정을 따르지 않는다 (핵심 문제)

원인이 세 겹으로 쌓여 있다.

1. **`SuhApiLogger`가 JUL(`java.util.logging`)을 직접 사용한다.**
   `util/SuhApiLogger.java:18`에서 `Logger.getLogger(clazz.getName())`를 호출한다.
   상위 프로젝트가 log4j2나 logback을 어떻게 설정하든 이 라이브러리의 로그는 JUL로 나간다.

2. **`build.gradle`이 로깅 의존성을 전역 exclude 한다.**
   `slf4j-api`, `logback-classic`, `spring-boot-starter-logging`, `jul-to-slf4j`,
   `log4j-to-slf4j`를 `configurations.all*.exclude`로 제외한다. 브리지조차 붙일 수 없다.
   더 심각한 건 이 exclude가 `maven-publish`로 배포되는 POM에 그대로 실려서
   **상위 프로젝트의 의존성 그래프까지 오염시킨다**는 점이다.

3. **라이브러리가 `application.yml`을 jar에 담아 배포한다.**
   `src/main/resources/application.yml`이 `logging.level.*`을 상위 프로젝트 classpath에
   밀어넣는다. 게다가 패키지명이 `me.suhsaechan.suhapilog`로 오타나 있어(실제는
   `kr.suhsaechan.suhapilog`) 의도한 효과조차 없다.

### 1.2 의존성 오염

- `api 'org.reflections:reflections:0.10.2'` — 소스 전체에서 **사용처 0건**인데 `api`
  스코프라 consumer에게 강제 노출된다. reflections는 javassist·slf4j-api를 끌고 오는데
  slf4j-api는 1.2에서 exclude되어 있어 실제로 쓰면 `NoClassDefFoundError`가 난다.
- `implementation springdoc-openapi-starter-webmvc-ui` — springdoc이 없어도 동작하도록
  리플렉션 `Proxy`로 짜놓고, 정작 런타임 의존성으로는 강제로 끌고 간다. 자기모순이다.

### 1.3 데드코드 약 590줄 (main 소스 1,400줄 중)

| 대상 | 줄 수 | 상태 |
|---|---:|---|
| `util/CommonUtil` | 420 | 사용처 0건. MultipartFile·JTS Geometry 직렬화 유틸로 이 라이브러리와 무관 |
| `config/ApiChangeLogConfiguration` | 89 | package-private, 사용처 0건. 자동설정과 중복 |
| `util/SuhTimeUtil` | 82 | 사용처 0건 |
| `SuhApiLogApplication` | 13 | 라이브러리 jar에 `@SpringBootApplication` main이 들어있다 |
| `GithubIssue.fetchedAt` | - | 필드·빌더는 있는데 한 번도 채워지지 않는다 |
| `IssueRepository.getCurrentHash()` / `findAll()` | - | 호출처 0건 |

### 1.4 버그

- **`GithubIssueService.java:160-186`** — `defaultAuthor` 폴백을 계산해 지역변수 `author`에
  담아놓고, 정작 출력할 때는 `escapeHtml(apiLog.author())`를 쓴다.
  `suhapilog.default-author` 설정이 **동작하지 않는다.**
- **`SuhApiLogAutoConfiguration.java:67`** — `@Bean public Object operationCustomizer(...)`.
  선언 반환 타입이 `Object`라 springdoc의 타입 기반 빈 수집에서 누락될 수 있고,
  실패 경로에서 `null`을 반환한다.
- **자동설정 이중 등록** — `@Configuration`과 `@AutoConfiguration`이 동시에 붙어 있고,
  `spring.factories`의 `EnableAutoConfiguration`(Boot 3 미지원)과 `.imports`에 중복 등록된다.
- **`JsonIssueRepository.saveIssues():108-109`** — 저장할 때마다 공유 `ObjectMapper`에
  `JavaTimeModule`을 재등록하고 `INDENT_OUTPUT`을 다시 켠다.
- **해시 주석/구현 불일치** — javadoc은 "MD5"인데 구현은 SHA-256이다.
- **HTML 테이블 생성 로직 중복** — `GithubIssueService.generateChangelogHtml`과
  `SwaggerIntegration.generateApiLogTable`이 같은 표를 두 벌 만들고, 이스케이프 규칙마저
  다르다(후자는 따옴표를 막지 않는다).

### 1.5 성능

- 부팅 시 이슈 N개를 **순차 blocking HTTP 스크래핑**한다. `Jsoup.connect()`에 timeout
  설정이 없어 GitHub가 느리면 그만큼 부팅이 매달린다.
- 조회 실패 이슈에 negative cache가 없어 Swagger UI를 열 때마다 재요청한다.
- `context.getBeansWithAnnotation(RestController.class)`가 모든 컨트롤러 빈을 강제로
  조기 초기화한다.
- `save()`가 호출될 때마다 JSON 파일 전체를 재작성한다. 동기화 시 O(n²) 쓰기가 된다.
- 계산해서 저장하는 해시를 아무도 읽지 않아, 변경이 없어도 매 기동마다 전량 재조회한다.

### 1.6 안정성 / 보안

- `SuhApiLogAutoConfiguration.java:133` — `base-url` 미설정 시 `IllegalStateException`으로
  **상위 애플리케이션 부팅을 죽인다.** 문서화 보조 라이브러리가 할 동작이 아니다.
- 파일 쓰기가 비원자적이라 쓰는 도중 프로세스가 죽으면 JSON이 깨진다.
- 파일 쓰기에 락이 없어 동시 요청 시 경합한다.
- `gradle.properties`에 Nexus 자격증명이 평문 커밋되어 있다
  (`nexusUsername=<제거됨>`, `nexusPassword=<제거됨>`). 이미 git 히스토리에 있다.
- 배포 리포지토리 URL이 https인데 `allowInsecureProtocol = true`가 켜져 있다.

## 2. 설계 원칙

1. **상위 프로젝트 설정이 언제나 우선한다.** 라이브러리는 아무 설정도 하지 않은 상태에서
   상위의 log4j2/logback 설정을 그대로 따른다. 상위가 막은 것을 라이브러리가 뚫지 않는다.
2. **모든 기본 동작은 옵션으로 열되, 기본값만으로 잘 돌아간다.**
3. **모든 주요 컴포넌트는 교체 가능하다.** 상위 프로젝트가 같은 타입 빈 하나만 등록하면
   라이브러리 수정 없이 동작이 바뀐다.
4. **라이브러리는 상위 앱을 죽이지 않는다.** 설정 오류는 경고 후 자기 비활성화가 기본이고,
   부팅 실패는 명시적으로 opt-in 했을 때만 일어난다.

## 3. 아키텍처

단일 아티팩트(`kr.suhsaechan:suh-api-log`)를 유지하고 내부만 레이어로 나눈다.
version.yml·CI 배포 워크플로우를 건드리지 않기 위한 선택이다.

```
kr.suhsaechan.suhapilog
├─ annotation/     @ApiLog, @ApiLogs                      (public API, 변경 없음)
├─ spi/            교체 가능 확장점 인터페이스 + 값 객체    (public API)
├─ logging/        SLF4J → Log4j2 → JUL 파사드
├─ core/           스프링 무관 순수 로직 (스캔·동기화)
├─ fetch/          JsoupIssueFetcher (기본 구현)
├─ storage/        JsonIssueRepository (기본 구현)
├─ render/         HtmlTableChangelogRenderer (기본 구현)
├─ integration/    springdoc 통합 (optional, @ConditionalOnClass)
└─ autoconfigure/  ApiChangeLogProperties, SuhApiLogAutoConfiguration
```

### 3.1 기존 클래스의 행선지

| 현재 | 3.0.0 | 비고 |
|---|---|---|

## 4. 로깅 파사드

### 4.1 구조

```
SuhLog.getLogger(Class)  →  SuhLogger (interface)
                              ├─ Slf4jLoggerAdapter    ← 1순위
                              ├─ Log4j2LoggerAdapter   ← 2순위
                              ├─ JulLoggerAdapter      ← 최종 폴백
                              └─ NoOpLogger            ← 차단용
```

`SuhLogger` 인터페이스: `trace/debug/info/warn/error` × (`String`, `String+Object...`,
`String+Throwable`) + `isXxxEnabled()`. 현재 없는 `trace` 레벨을 추가한다.

### 4.2 백엔드 탐지

`LoggerBackendResolver`가 최초 1회 탐지하고 결과를 `volatile static`에 캐싱한다.

1. `suhapilog.logging.backend`가 `auto`가 아니면 그 값을 사용한다.
2. `Class.forName("org.slf4j.LoggerFactory")` 성공 → **단, 바인딩 확인**:
   `LoggerFactory.getILoggerFactory().getClass().getName()`에 `NOP`가 포함되면
   (SLF4J 2.x가 provider를 못 찾은 상태) 다음 후보로 넘어간다.
3. `Class.forName("org.apache.logging.log4j.LogManager")` 성공 → Log4j2 어댑터.
4. 전부 실패 → JUL 어댑터.

어댑터 클래스는 탐지 성공 **이후에만** 로드된다. 따라서 slf4j-api가 클래스패스에 없어도
`NoClassDefFoundError`가 발생하지 않는다.

> 상위가 `spring-boot-starter-log4j2`를 쓰면 slf4j-api와 log4j-api가 둘 다 존재하고
> slf4j가 `log4j-slf4j2-impl`을 통해 log4j2로 라우팅된다. 1순위 SLF4J로도 결국
> log4j2 설정이 적용되므로 탐지 순서는 이대로가 맞다.

### 4.3 포맷팅 위임 (성능)

현재 `SuhApiLogger.formatMessage()`는 `{}` 플레이스홀더를 직접 파싱해 문자열을 조립한다
(50줄). SLF4J와 Log4j2는 `{}`를 네이티브 지원하며 **레벨이 비활성이면 포맷팅 자체를
수행하지 않는다.** 어댑터는 인자를 그대로 백엔드에 넘겨 이 최적화를 그대로 얻는다.
자체 포맷팅은 JUL 폴백 경로에서만 사용한다(기존 구현을 `JulMessageFormatter`로 이관).

### 4.4 정적 로거 초기화 타이밍

로거는 `private static final`로 클래스 로딩 시점에 생성되는데, Spring 프로퍼티는 그보다
늦게 읽힌다. 해결:

- `SuhLogSettings` — `volatile static` 설정 홀더. 기본값은 "전부 상위에 위임".
- `SuhApiLogEnvironmentPostProcessor implements EnvironmentPostProcessor, Ordered` —
  `suhapilog.logging.*`를 읽어 홀더에 주입한다. `Ordered.LOWEST_PRECEDENCE`로 등록해
  `ConfigDataEnvironmentPostProcessor` 이후에 실행되도록 하여 application.yml 값을 본다.
  `META-INF/spring.factories`의 `org.springframework.boot.env.EnvironmentPostProcessor`
  키로 등록한다 (이 키는 Boot 3에서도 유효하다).
- 어댑터는 매 호출 시 홀더를 읽는다(volatile read, 무시 가능한 비용). 설정이 나중에
  바뀌어도 즉시 반영된다.

### 4.5 오버라이드 옵션

| 키 | 기본값 | 동작 |
|---|---|---|
| `suhapilog.logging.enabled` | `true` | `false`면 `NoOpLogger`로 전면 차단 |
| `suhapilog.logging.level` | *(미설정)* | 이 레벨 미만 메시지를 라이브러리 단에서 드롭 |
| `suhapilog.logging.backend` | `auto` | `auto`/`slf4j`/`log4j2`/`jul`/`none` |

**`logging.level`의 정확한 의미(중요)**: 이 옵션은 **추가 필터**다. 상위가 이미 허용한
범위를 좁힐 수만 있고, 상위가 막은 레벨을 열지는 못한다. 설계 원칙 1을 지키기 위한
의도적 선택이다. 로그를 더 보고 싶으면 상위 log4j2/logback 설정에서 `kr.suhsaechan`
로거 레벨을 조정해야 하며, README에 그 방법을 명시한다.

### 4.6 빌드 변경

- `configurations { all*.exclude ... }` 로깅 exclude 블록 **전부 삭제**
- `compileOnly 'org.slf4j:slf4j-api'`, `compileOnly 'org.apache.logging.log4j:log4j-api'` 추가
- `src/main/resources/application.yml`, `application-test.yml` **삭제**
- 검증: `./gradlew generatePomFileForMavenJavaPublication` 결과 POM에 로깅 관련
  `<exclusions>`가 없는지 확인한다

### 4.7 하위 호환

`util.SuhApiLogger`는 public 클래스였으므로 **삭제하지 않고 `@Deprecated` 위임 shim으로
남긴다**. 내부적으로 `SuhLog`에 위임하며 3.1.0에서 제거 예정임을 javadoc에 명시한다.

## 5. 확장점(SPI)

`kr.suhsaechan.suhapilog.spi` 패키지. 전부 자동설정에서 `@ConditionalOnMissingBean`으로
등록되므로, 상위 프로젝트가 같은 타입 빈을 하나 등록하면 기본 구현이 물러난다.

```java
public interface IssueFetcher {
    Optional<IssueRef> fetch(int issueNumber);
}

public interface IssueRepository {
    Optional<IssueRef> findByIssueNumber(int issueNumber);
    IssueRef save(IssueRef issue);
    Collection<IssueRef> findAll();
    void saveAll(Collection<IssueRef> issues);
    String getCurrentHash();
    void updateHash(String hash);
}

public interface ChangelogRenderer {
    String render(List<ApiLogEntry> entries);
}

public interface TitleNormalizer {
    String normalize(String rawTitle);
}
```

| SPI | 기본 구현 | 교체 사용 예 |
|---|---|---|
| `IssueFetcher` | `JsoupIssueFetcher` | GitLab·Jira·사내 트래커 연동 |
| `IssueRepository` | `JsonIssueRepository` | Redis·DB·인메모리 캐시 |
| `ChangelogRenderer` | `HtmlTableChangelogRenderer` | 카드형·타임라인형 렌더링 |
| `TitleNormalizer` | `DefaultTitleNormalizer` | 팀별 이슈 제목 컨벤션 |

**`ApiLogEntry`** — 렌더러에 어노테이션을 그대로 넘기지 않고, 정규화가 끝난 불변 값
객체를 넘긴다(author 폴백 적용 완료, 이슈 제목 resolve 완료, 이슈 URL 생성 완료).
렌더러 구현자가 `@ApiLog` 어노테이션 API에 결합되지 않게 하기 위함이다.

**`IssueRef`** — 기존 `GithubIssue`를 대체하는 SPI 레벨 모델. `fetchedAt`을 실제로 채운다.
`GithubIssue`는 `@Deprecated`로 남기고 `IssueRef`에 위임한다.

## 6. 렌더링

앞 세 개만 처리).

## 7. GitHub 이슈 조회

기본 구현은 jsoup 스크래핑을 유지하되 아래 옵션을 추가한다.

| 키 | 기본값 | 이유 |
|---|---|---|
| `suhapilog.github.base-url` | *(없음)* | 기존 |
| `suhapilog.github.timeout` | `5s` | **현재 타임아웃 없음.** jsoup의 `Connection` API는 connect/read를 분리하지 않고 총 요청 시간 하나만 받으므로 단일 옵션으로 통합했다. 분리가 필요하면 `IssueFetcher` SPI로 교체한다 |
| `suhapilog.github.retry.max-attempts` | `2` | 일시 실패 흡수 |
| `suhapilog.github.retry.backoff` | `500ms` | |
| `suhapilog.github.user-agent` | `suh-api-log/{version}` | 스크래핑 차단 회피 |

`{version}`은 `SuhApiLogVersion.get()`이 반환한다. 구현은
`SuhApiLogVersion.class.getPackage().getImplementationVersion()`을 읽고, jar 매니페스트가
없는 환경(IDE 실행·테스트)에서는 `"dev"`로 폴백한다. jar 매니페스트에 버전이 실리도록
`build.gradle`의 `jar` 태스크에 `Implementation-Version` 속성을 추가한다.
| `suhapilog.github.concurrency` | `4` | 순차 → 병렬 (고정 크기 풀, 완료 후 shutdown) |
| `suhapilog.github.startup-mode` | `async` | `blocking`/`async`/`lazy`. 부팅 블로킹 제거 |
| `suhapilog.github.fail-fast` | `false` | 설정 오류 시 경고 후 자기 비활성화가 기본 |
| `suhapilog.github.cache.ttl` | *(무기한)* | `fetchedAt` 기준 만료 재조회 |
| `suhapilog.github.cache.negative-ttl` | `10m` | 실패 이슈 재요청 폭주 차단 |

**`startup-mode` 의미**
- `blocking` — 기존 동작. 부팅 중 전량 동기화 완료까지 대기
- `async` (기본) — 백그라운드 스레드로 워밍업. 그 사이 들어온 요청은 lazy fetch가 커버
- `lazy` — 부팅 시 아무것도 안 하고 Swagger 렌더 시점에만 조회

**`fail-fast=false`일 때의 동작**: `base-url`이 없으면 `WARN` 한 줄을 남기고 이슈 연동
기능만 끈다. `@ApiLog`의 날짜·작성자·설명은 정상 렌더링된다. `true`면 기존처럼
`IllegalStateException`을 던진다.

## 8. 부팅 스캔

- **컨트롤러 수집**: `RequestMappingHandlerMapping.getHandlerMethods()`를 우선 사용하고,
  해당 빈이 없으면 `ListableBeanFactory.getBeanNamesForAnnotation`으로 빈 **정의**만
  훑는다. 현재의 `getBeansWithAnnotation`처럼 모든 컨트롤러를 강제 조기 초기화하지 않는다.
- **CGLIB 언랩**: `clazz.getName().contains("$$")` → `ClassUtils.getUserClass(clazz)`
- **어노테이션 탐색**: `MergedAnnotations.SearchStrategy.TYPE_HIERARCHY`로 통일한다.
  현재 `ChangelogProcessor`는 수동 인터페이스 순회, `SwaggerIntegration`은
  `MergedAnnotations`를 쓰고 있어 결과가 어긋날 수 있다.
- **해시 활용**: 스캔된 이슈 번호 집합의 SHA-256이 저장된 해시와 같고 캐시 항목이 전부
  유효하면 네트워크 조회를 통째로 건너뛴다. 변경 없는 재기동에서 HTTP 요청 0회가 된다.

## 9. 자동설정 정리

- `@Configuration` + `@AutoConfiguration` 중복 제거 → `@AutoConfiguration`만 사용
- `META-INF/spring.factories`에서 `EnableAutoConfiguration` 항목 삭제(Boot 3 미지원).
  파일 자체는 `EnvironmentPostProcessor` 등록용으로 존치한다.
- `@EnableConfigurationProperties(ApiChangeLogProperties.class)` +
  `ApiChangeLogProperties` 클래스에 `@ConfigurationProperties(prefix = "suhapilog")`
- **springdoc 통합 재작성**: 리플렉션 `Proxy` 제거. `@ConditionalOnClass(OperationCustomizer.class)`
  중첩 설정에서 `OperationCustomizer`를 직접 구현한다. springdoc은 `compileOnly`로 내린다.
- `annotationProcessor 'org.springframework.boot:spring-boot-configuration-processor'` 추가
  → IDE 자동완성 및 설정 문서화
- `sourceCompatibility = '17'` → `java { toolchain { languageVersion = JavaLanguageVersion.of(17) } }`

## 10. 저장소 견고성

- **원자적 쓰기**: temp 파일에 쓴 뒤 `Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)`.
  `ATOMIC_MOVE` 미지원 파일시스템에서는 `REPLACE_EXISTING`으로 폴백한다.
- **ObjectMapper 1회 구성**: 생성자에서 `JavaTimeModule` 등록 + `INDENT_OUTPUT` 설정.
  `saveIssues()` 안의 재설정 코드를 제거한다.
- **쓰기 횟수 축소**: `saveAll`은 파일 쓰기 1회. 현재는 건별 `save()`가 전체 파일을
  재작성해 O(n²)이다.
- **`ReentrantLock`으로 파일 쓰기 직렬화**
- `HexFormat.of().formatHex()` 사용, "MD5"라 적힌 javadoc을 SHA-256으로 정정
- `Files.readString/writeString`에 `StandardCharsets.UTF_8` 명시
